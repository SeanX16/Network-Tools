## v3 扩展范围

- 保存请求覆盖 `sns-video-*.xhscdn.com`，以及数字后缀的 `sns-vN.xhscdn.com`、`sns-vN.rednotecdn.com`。例如已在用户样本中出现的 v14、v2、v6、zl，以及其他匹配该域名族的节点。不会匹配任意第三方域名。
- 原视频尺寸不再限定 1080P：短边至少 1080、最多 2160，长边最多 4096，支持横竖屏的 1440×2560、2160×3840、3840×2160、4096×2160 等。只有像素面积高于当前兼容流且时长匹配时才替换，不会把低清视频放大，也不会降低已有 2K/4K 保存候选的分辨率。
- 不再依赖 App 申报的源宽高高于播放流才记录分享信息。保存时以实际原文件的尺寸判断是否可提升，避免 App 元数据不完整时漏掉更高分辨率源文件。
- MP4 元数据读取上限由 256 KiB 增至 1 MiB，便于处理采样表较大的文件；仍保留总截止时间和格式检查。
- 播放响应、兼容选流、默认版本和播放缓存地址保持 v2 原样；播放阶段仍不查询原视频。

当前继续限定已观察到的 iPhone 9.53 保存请求特征；没有扩大到未知客户端版本。H.264/HEVC 的原有编码配置检查也保留：8-bit、未旋转、单 AAC 音轨等条件仍适用，HDR/Main10、特殊轨道或未知容器结构可能回退。扩展的是保存请求识别和原文件分辨率，原视频资源仍从已验证的 `sns-video-bd.xhscdn.com` 获取。

v2 已由用户确认：这条笔记播放正常、相册保存为二十多 MB 的 1080P HEVC，两份日志对应兼容播放与独立下载 307。v3 的真实 1440P 文件和生成的有效 4K 文件已通过本地解码与脚本回放；其他 CDN、2K/4K 的 iPhone 相册保存仍待实际样本验证。

## 本次抓包与修正

用户实测 v1 播放正常，但长按保存仍为 720P H.264。新 HAR 中没有 v10 保存接口请求；实际保存直接 GET 视频 CDN 的 258.mp4，HTTP 200，文件 3,146,817 字节。提取文件确认为 720×1280 H.264 + AAC，因此 v1 的 v10 地址替换没有覆盖该路径。

本次保存请求使用 `discover/9.53 (iPhone; ...)`，没有 Range，Referer 为 `https://app.xhs.cn/`。已观察到的播放/预加载请求使用 `IOS-RedDownload-player/preload-0`，带 Range。本版根据这些实际差异窄匹配；这不是平台保证的永久保存标志，不承诺覆盖其他版本或所有播放场景。

v3 对上述小红书视频 CDN 域名族使用 `script-response-header` 规则。只有同时满足以下条件才探测原视频：

- GET，响应 HTTP 200、Content-Type 为 video/mp4 或 application/octet-stream；仍须是缓存中精确匹配的 MP4 路径和文件大小。
- User-Agent 匹配本次 iPhone `discover/9.53`，Referer 一致，无 Range 或 If-Range。
- 资源路径唯一匹配信息流缓存，Content-Length 与缓存的兼容视频大小一致。
- 同一笔记的保存信息在一小时内生成；最终由原文件元数据确认是否比当前兼容流更清晰。

探测通过后返回 **307 Temporary Redirect**，指向原视频。设置 `Cache-Control: no-store`，避免保存跳转被缓存后复用于播放。播放器、预加载、Range、未知客户端、不匹配请求、探测失败及超时均原样放行。

此前原视频播放候选注入曾导致 App 闪退，已撤回。**v3 不向播放候选注入原视频，不伪造播放流类型、尺寸或编码字段。**真实信息流回放中，发送给 App 的播放 JSON 与正式回退版相同。

## 日志

查找脚本 `xhs-original-save-test.js` 和前缀 `[仅保存原视频 v3]`：

- `命中独立保存下载请求`：请求符合当前筛选条件。
- `找到 宽×高 编码`（例如 `找到 2160×3840 hevc`）：原视频通过元数据检查，日志显示实际尺寸。
- `独立下载已返回 307 原视频跳转；播放请求未改动`：已返回跳转，尚不代表相册写入成功。
- `原视频未就绪，放行原下载` / `下载探测失败，放行原下载`：继续下载兼容视频。

v10 支持保留，对应日志为 `收到 v10 保存响应` 和 `已替换保存地址`。本次抓包实际走独立下载，不依赖 v10。

如果仍是 720P，先检查是否有“命中独立保存下载请求”和“307”日志。没有命中可能是配置或脚本未同时更新、缓存未刷新、App 复用本地文件，或请求特征与当前规则不同。

## 范围与限制

- 正式版保持回退状态。图片、实况、净化和下载按钮功能沿用正式版。
- 信息流阶段不新增网络请求，仅向原有 `redBookVideoFeed` 缓存附加保存信息；缓存中的 `url` 始终是兼容播放地址，没有新增缓存键。
- 原视频检查截止时间 6.5 秒。只接受已支持的普通 MP4 配置、单 AAC 音轨、未旋转且短边 1080–2160/长边不超过 4096、分辨率更高、时长接近的资源。ef51 或未知结构不使用。运行时只检查元数据，不整段解码或转码。
- CDN 规则只覆盖上述小红书视频域名族，没有扩展到任意域名或未知客户端。
- 响应头规则在原服务器响应头到达后执行，不由脚本替换或代理响应体，保留原实体长度与类型。客户端可能传输部分甚至全部低清响应体后才跟随跳转，不能保证只消耗原视频流量。
- 不能检测后续下载或相册写入是否成功，也不能在写入失败后自动重试兼容文件。已成功的 1080P 样本不能证明其他 CDN、2K/4K 或所有场景都已实机通过。
