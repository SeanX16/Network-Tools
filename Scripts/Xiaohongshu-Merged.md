2026-11-12：正式版 v8.1 取消原文件至少 1080P 的旧门槛，其余检查保持不变。此前已合入测试版 v8。保留 fmz200 原版净化、去广告、下载按钮、图片及实况功能，默认保存静态图片原尺寸资源；视频播放交给 APP 自行选画质，视频保存独立优先平台原文件，并保留兼容流兜底。

## 安装和升级

正式订阅地址保持不变：

https://raw.githubusercontent.com/SeanX16/Network-Tools/main/Scripts/Xiaohongshu-Merged.conf

1. 更新正式订阅资源和引用脚本 `xhs-merged.js`。本次同时新增视频 CDN 响应头规则和 MitM 域名，不能只更新 JS。
2. 只启用正式整合版，停用 `Xiaohongshu-Original-Save-Test.conf`、其他小红书测试订阅、fmz200 原版和独立高清保存版，避免规则重复命中。
3. 确认 QX 重写、MitM 和证书信任正常，退出小红书后重新打开笔记，让完整候选和保存缓存重新生成。日志前缀为 `[原视频保存 v8.1]`。
4. 若仍复用旧播放画质，清理小红书自己的媒体缓存后重开。QX 缓存清除任务只清除链接文本，不清理 App 媒体文件。

## 视频播放和保存

- 完整保留服务器提供的播放候选、顺序、默认标记和媒体参数，由 APP 自行选择或切换画质。播放阶段不探测、不注入原视频地址，不强制最高画质。
- 保存时独立匹配同笔记各候选的媒体路径和文件大小，包括合法备用地址，不再要求播放使用兼容白名单内的版本。
- 原文件来自同笔记已验证的 `originVideoKey`。完成身份、封装、编码、尺寸和时长检查后，原文件总像素数不低于保存参考候选即可使用；同为 720P 或更低分辨率时也允许保存原文件，不再要求至少 1080P。
- 支持最高 4K、H.264、HEVC 8/10-bit、HDR10/PQ、HLG 和杜比视界 8.1/8.4。仅返回文件地址，不转码、不删除拍摄或 HDR 元数据。
- 原文件不可用时保留已验证兼容候选的保存兜底。兼容白名单只用于保存兜底，不限制 APP 播放；没有可安全匹配的兜底时原样放行。后续相册写入失败不能由脚本自动恢复。
- 独立下载仅匹配已观察到的 iPhone `discover/9.53`、GET、HTTP 200、指定 Referer、无 Range/If-Range、正确 Content-Type、唯一媒体路径及一致大小。播放器、预加载、未知客户端、歧义或不匹配请求不触发探测。v10 保存接口继续支持。
- 保存跳转禁止缓存；兼容候选不会跳转到自身。客户端跟随兜底后可能再次探测原文件，但不会因原文件不可用形成跳转循环。客户端也可能在跟随跳转前已接收部分原下载数据，不能保证只消耗一份视频的流量。
- 保存缓存沿用 `redBookVideoFeed`，最近最多 20 条笔记，一小时过期；每条最多扫描 64 个流、每流 8 个备用地址、最多记录 128 个路径。冲突路径拒绝匹配，新的 DRM/无效笔记会移除同 ID 的旧缓存。

平台原文件不保证是相机原片，不保证带有设备、位置等元数据，也不保证其视觉锐度高于 APP 内的播放版本。`ef51` 播放流的解码与画质比较仍单独研究，未作为可直接保存的兼容格式加入正式版。

## 保留的其他功能

原配置全部启用规则和原作者署名保留，包括广告域名拦截、弹窗及引导拦截、搜索净化、开屏处理、详情页小部件、图片及实况保存、视频下载权限和按钮，以及原有实验性评论区规则。原来注释的规则仍保持注释，不扩大启用范围。五条 `host, ..., reject` 属于域名分流规则；若 QX 在重写资源中忽略它们，需要放入分流规则才能实际拦截。原版本自身未生效或实验性的功能不因合并而保证有效。

## 验证与实机范围

正式版 v8.1 在已验证的 v8 基础上，只删除原文件短边至少 1080 的条件；除此之外仅更新版本标记，其他脚本逻辑逐字一致。测试覆盖完整原生播放候选保留、两条真实笔记保存、每条五种候选与 v10 保存回放、备用路径、旧缓存、跨笔记缓存、过期/冲突/Range/未知客户端拒绝、兼容兜底无循环、超时和迟到响应、图片功能，以及既有 1080P/4K 原文件、13 类封装和 5 类 HDR 样本。

此前抓包已记录 APP 实际下载完整 1080P 339 播放流，同时保存请求跳转并完整下载 1080P 标准 HEVC 原文件；原文件与前次下载逐字节一致。此前也有多条相册保存反馈。上述结果不等于覆盖所有笔记、未来 App 版本或全部 HDR 相册显示场景。

新增 720P 真实抓包回放：原文件 720×1280、HEVC、13,653,460 字节，通过完整音视频解码；旧版因 1080P 门槛回退到 720P H.264，新版在同一响应回放中正确返回原文件地址。仍拒绝原文件分辨率低于保存参考候选的情况。此次属于本地回放验证，更新后的手机相册保存仍需实机确认。

## 仍保留的限制

- 一个视频轨，H.264 avc1（Baseline/Main/High）或 8/10-bit 4:2:0 HEVC Main/Main10 hvc1；零至八个单声道／立体声 AAC 音轨。每个音视频轨最多 16 个描述。
- 原视频尺寸必须有效，短边不超过 2160、长边不超过 4096，像素面积必须不低于命中的保存候选（v10 无匹配地址时采用缓存参考候选），视频时长与该候选相差不超过 1.5 秒；不放大低清视频。
- 保留 DRM、编码和尺寸检查。12-bit、4:2:2/4:4:4、H.264 High10、杜比视界 Profile 5/7 或双层／压缩动态元数据、ef51、hev1/avc3、其他编码、多视频轨、分片或压缩 movie 元数据等仍回退，不宣称支持所有合法媒体。
- 原视频探测总截止时间仍为 6.5 秒；媒体分段请求最多 8 次，moov 最大 1 MiB，分段响应累计最多 1,146,880 字节，顶层扫描最多 64 个 box。资源超限会回退，不会为兼容性无限下载。
- 运行时只检查容器元数据和分段响应一致性，不整段解码、不转码；不能保证媒体载荷完整，也不能预知 iPhone 相册是否接受该文件。后续下载或相册写入失败不能由脚本自动恢复。

## 日志

查找 `[原视频保存 v8.1]`：

- `命中独立保存下载请求`：请求符合筛选条件。
- `找到 宽×高 编码`：原视频通过元数据和选流条件检查。
- `独立下载已返回 307 原视频跳转；播放请求未改动`：已返回跳转。
- `原文件不可用，独立下载已返回 307 兼容流兜底`：原文件未通过检查，保存回到已知兼容候选。
- `原视频检查回退：原因码`：例如 `probe-timeout`（超时）、`range-response`（分段响应异常）、`box-boundary`（容器边界异常）、`video-sample-type`（视频样本类型未支持）、`hevc-profile-or-depth`（HEVC 配置不支持）、`network-or-page`（网络或网页解析失败）。日志不输出请求头、签名地址或网页正文。
- `未找到符合条件的原视频`：分享页／资源未找到，或尺寸、时长不符合切换条件。


## 静态图片原尺寸保存

默认使用图片完整 `fileid` 对应的 `https://sns-img-bd.xhscdn.com/<fileid>` 资源，不设置 1440、2160 或 5000 的缩放上限，也不强制转换为 PNG。这里的“原尺寸”指平台能提供的源资源，不保证与作者上传前的文件逐字节一致。

- 完整保留 `notes_pre_post/` 等资源目录；不只截取文件名。
- 对第一组图文信息流里的每条笔记、每张静态图片处理，统一 `url`、`url_size_large`、`original`，以及已有的 `url_multi_level`、`url_8k`、`hd_img.url`，避免 App 保存时又选中缩略图。
- 保留接口的宽高和原图元数据；图片缓存记录实际返回给 App 的图片信息。
- 为避免保存时复用低分辨率预览，预览地址也使用原尺寸资源，浏览图文可能增加流量和加载时间。
- 实况图片、缺少合法 `fileid` 的图片沿用原版 2160 增强流程；实况的视频数据不改动。未增加评论图片原图处理规则。
- 未设置画质偏好时默认原尺寸；已有 `fmz200.xiaohongshu.imageQuality=original` 同样使用新逻辑。显式设置其他非空值时，继续使用原版 2160 模式。
- 源资源的可用性和格式由平台决定；当前只做同步地址改写，不在每次信息流内发请求探测或自动重试备用 CDN。

已用用户提供的三张图片缓存回放测试，并实际下载原尺寸资源核对：
第一张 JPEG 为 3072×5461，第二张为 3456×6143，第三张为 3072×5461。首图原接口的详情地址返回 1440×2560；旧脚本改为 2160 后返回 2160×3840；接口标为 `original` 的地址仍有 5000 上限，返回 2814×5000。上述结论来自实际文件尺寸，不只根据 URL 参数判断。用户提供的完整日志及签名链接不包含在仓库内。

更新整合订阅及引用的 `xhs-merged.js` 后，退出小红书再重新打开笔记。执行日志应出现 `[小红书原图] 已切换`，图片缓存中的地址应指向 `sns-img-bd.xhscdn.com`。再保存到相册检查像素尺寸；必要时清除小红书自己的图片缓存后重试，QX 的四项持久化缓存与小红书 App 的图片缓存是分开的。

## 手动查看和清除缓存

KB 按缓存原始文本的 UTF-8 编码字节数计算，1 KB = 1024 字节，保留两位小数。它表示缓存文本大小，不代表图片/视频文件大小，也不等于 QX 底层数据库的实际磁盘占用；字符数保留原有 JavaScript 字符串长度统计口径。

两个独立任务脚本：

- [查看缓存](https://raw.githubusercontent.com/SeanX16/Network-Tools/main/Scripts/xhs-cache-view.js)：通知显示各项状态、字符数和 KB 大小，并显示合计；完整内容输出到本次执行日志；只读。
- [清除缓存](https://raw.githubusercontent.com/SeanX16/Network-Tools/main/Scripts/xhs-cache-clear.js)：仅清除普通视频、图片/实况、评论实况、评论视频四项缓存，逐项读回确认结果；保留图片画质设置和其他脚本数据。

进入 QX「设置 → 配置文件 → 编辑」，在已有的 `[task_local]` 段下添加下面两行；没有该段时才新建 `[task_local]`：

```ini
0 0 * * * https://raw.githubusercontent.com/SeanX16/Network-Tools/main/Scripts/xhs-cache-view.js, tag=小红书缓存查看, enabled=false
0 0 * * * https://raw.githubusercontent.com/SeanX16/Network-Tools/main/Scripts/xhs-cache-clear.js, tag=小红书缓存清除, enabled=false
```

两项均设置为 `enabled=false`，不自动定时执行。保存后进入「HTTP 请求／构造请求」列表，在对应任务上右滑，点击运行按钮手动执行；查看任务的执行日志可读到具体内容。若开启了 QX 通知权限，也会收到结果通知。不要为了手动运行而打开定时开关。

清除前先退出小红书，避免重写脚本同时写回缓存。清除后重新打开笔记或视频，会重新生成缓存；已保存到相册的内容不受影响。原版和整合版共用这些缓存名称，所以清除会同时影响两者。评论相关项暂无缓存是正常情况。

两份脚本本身没有网络请求；首次添加或更新脚本时，由 QX 从 GitHub 下载代码。查看脚本会把缓存中的笔记 ID 和带参数的视频链接写入本机执行日志，分享日志时可先隐去这些内容。

已用模拟 QX 环境验证只读查看、四项定向删除、重复清除、读写失败反馈与其他数据保留；尚未在 iPhone 实机执行。
